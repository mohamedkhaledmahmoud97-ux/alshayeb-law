# Contributing Guide — ALSHAYEB LAW

Version 1.0

---

# Welcome

Thank you for your interest in contributing to ALSHAYEB LAW.

This project aims to build a high-quality Egyptian Legal Retrieval-Augmented Generation (RAG) system while maintaining academic rigor, software engineering best practices, and reproducible research.

Every contribution should improve the project's quality, maintainability, or reproducibility.

---

# Contribution Principles

All contributions should follow these principles:

- Evidence over assumptions.
- Documentation before implementation.
- Small, focused changes.
- Clear commit history.
- Reproducible development.
- Respect for repository structure.

---

# Repository Workflow

Contributors should follow this workflow:

1. Review the project documentation.
2. Read the relevant Architecture Decision Records (ADRs).
3. Check the TODO backlog.
4. Implement a single logical change.
5. Update documentation if necessary.
6. Commit using a descriptive message.
7. Open a Pull Request (for collaborative development).

---

# Branch Strategy

Recommended branch names:

- feature/...
- fix/...
- docs/...
- benchmark/...
- dataset/...
- refactor/...

Examples:

- feature/retrieval-engine
- docs/update-architecture
- benchmark/query-sets

---

# Commit Message Guidelines

Use short, descriptive commit messages.

Examples:

- Add retrieval evaluation metrics
- Improve benchmark documentation
- Update architecture diagram
- Fix citation validation logic

Avoid messages such as:

- update
- changes
- fix
- work
- new file

---

# Documentation Standards

All documentation must:

- Be written in English.
- Use Markdown.
- Follow consistent heading levels.
- Be technically accurate.
- Avoid unnecessary repetition.
- Stay synchronized with implementation.

---

# Code Standards

Source code should:

- Follow Python best practices.
- Use meaningful names.
- Include comments only when necessary.
- Be modular.
- Be easy to test.

---

# AI Contribution Guidelines

AI-generated content is welcome but must always be reviewed by a human before acceptance.

AI assistants should:

- Never invent legal citations.
- Never fabricate legal articles.
- Clearly identify uncertain information.
- Follow the instructions defined in AI_CONTEXT.md.

---

# Benchmark Contributions

Benchmark updates should include:

- Query definitions.
- Gold labels.
- Relevance grading.
- Evaluation notes.
- Version information.

---

# Dataset Contributions

Datasets should include:

- Source information.
- Metadata.
- Version number.
- Processing notes.

Raw and processed datasets must remain separated.

---

# Pull Request Checklist

Before submitting a Pull Request, verify that:

- Documentation is updated.
- No unrelated files were modified.
- File names follow project conventions.
- Markdown formatting is correct.
- The project structure remains consistent.

---

# Reporting Issues

When reporting an issue, include:

- Description
- Steps to reproduce
- Expected behavior
- Actual behavior
- Suggested improvement (if applicable)

---

# Code of Conduct

All contributors are expected to follow the project's Code of Conduct.

Respectful, constructive, and professional collaboration is required at all times.

---

# Thank You

Every contribution, whether documentation, datasets, benchmarks, or source code, helps improve ALSHAYEB LAW and supports the development of trustworthy Egyptian Legal AI systems.
