# PROJECT_SPEC

## 1. Project Title

ALSHAYEB-LAW

## 2. Project Definition

ALSHAYEB-LAW is an Egyptian Legal Retrieval-Augmented Generation (RAG) project focused on building a legally grounded AI assistant and evaluating it using a formal academic benchmarking framework.

## 3. Problem Statement

Legal AI systems can produce fluent but unsupported answers if they are not carefully evaluated. This project addresses the need for a reliable Egyptian legal RAG framework that emphasizes source grounding, citation correctness, legal correctness, and reproducibility.

## 4. Project Goals

- Build a formal benchmark for Egyptian legal queries.
- Define gold labels and relevance grades.
- Measure retrieval, reranking, and generation quality.
- Evaluate citation recall and citation faithfulness.
- Analyze error patterns.
- Produce an academic report.
- Maintain a structured and reproducible repository.

## 5. Scope

The project includes:
- statute-only retrieval,
- doctrine retrieval,
- case-law retrieval,
- exact article lookup,
- legal issue-to-rule mapping,
- multi-hop legal reasoning,
- Arabic variation testing,
- dialect normalization,
- hard negatives,
- citation validation,
- evaluation reporting.

## 6. Out of Scope

The project does not aim to:
- replace human legal judgment,
- provide binding legal opinions,
- invent or infer unsupported legal claims,
- simulate legal authority without evidence.

## 7. Core Deliverables

1. Academic evaluation report.
2. Appendix pack with tables and rubrics.
3. Benchmark files and gold labels.
4. Claude project instructions.
5. GitHub repository with structured documentation.
6. Final exported submission copy.

## 8. Evaluation Dimensions

- Retrieval quality.
- Reranking quality.
- Citation recall.
- Citation accuracy.
- Answer faithfulness.
- Legal correctness.
- Robustness.
- Latency.
- Throughput.
- Memory footprint.
- Error analysis.

## 9. Benchmark Slices

- Statute-only queries.
- Doctrine queries.
- Case-law queries.
- Exact lookup tasks.
- Rule-to-application tasks.
- Multi-hop reasoning tasks.
- Arabic variation tasks.
- Dialect normalization tasks.
- Hard negative tasks.

## 10. Success Criteria

The project will be considered successful when:
- the documentation is complete,
- the benchmark is clearly specified,
- the system evaluation is reproducible,
- citations are accurate,
- unsupported answers are minimized,
- and the final report is academically polished.
