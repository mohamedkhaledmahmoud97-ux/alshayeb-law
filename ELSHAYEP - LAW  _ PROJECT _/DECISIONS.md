# DECISIONS

## Decision 1: Use Markdown for all core documentation
Reason: Markdown is easy to version, review, and convert to other formats.

## Decision 2: Separate report and appendix files
Reason: It improves clarity and makes the project easier to maintain.

## Decision 3: Keep AI instructions in a dedicated file
Reason: This ensures Claude uses consistent rules across sessions.

## Decision 4: Store benchmarks separately from documentation
Reason: It preserves cleanliness and version control.

## Decision 5: Keep outputs isolated
Reason: It prevents generated artifacts from mixing with source materials.

## Decision 6: Use a master project plan file
Reason: It centralizes execution rules, file responsibilities, and workflow.

## Decision 7: Avoid unsupported legal assertions
Reason: The project must remain academically defensible and grounded.

## Decision 8: Use GitHub as the source of truth
Reason: It ensures traceability and version history.
